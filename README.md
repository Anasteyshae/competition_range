# competition_range

## Описание задачи

Цель соревнования — ранжирование русскоязычных поисковых результатов по степени релевантности запросу. В качестве основной метрики используется средний NDCG@10 по запросам.

Обучающая выборка содержит 31 530 наблюдений и 3 042 уникальных запроса, тестовая — 13 507 наблюдений и 1 305 запросов.

Для дообучения моделей использовались исключительно данные соревнования.

## Предобработка данных

На этапе подготовки данных выполнялись:

- исправление ошибок кодировки;
- нормализация Unicode;
- удаление HTML-тегов, управляющих символов и лишних пробелов;
- восстановление пропущенных заголовков по идентификаторам документов;
- нормализация текстов поисковых запросов;
- стемминг для расчёта лексического сходства.

Количество наблюдений и состав документов для каждого запроса сохранялись.

## Валидация

Разбиение выполнено по связанным компонентам запросов и документов, чтобы минимизировать утечку данных между обучающей и валидационной выборками.

Для дообучения использовался 2 521 запрос, для валидации — 521 запрос.

Валидационная выборка дополнительно разделена на две части:

- 237 запросов для обучения калибратора;
- 284 запроса для проверки качества объединения моделей.

Random seed для разбиения — 839127.

## Описание модели

В качестве основной архитектуры использована предобученная модель jinaai/jina-reranker-v3.5.

Итоговое решение состоит из двух моделей:

- Full Jina — ранжирование полного списка документов;
- Shortlist Jina — уточнение ранжирования наиболее релевантных документов.

Обе модели дообучались методом LoRA на данных соревнования.

Основные параметры обучения:

- LoRA rank — 8;
- LoRA alpha — 16;
- LoRA dropout — 0.05;
- оптимизатор — AdamW;
- learning rate для LoRA — 1e-5;
- learning rate для проектора — 5e-6;
- количество эпох — 1;
- точность вычислений — FP16.

В основной модели адаптировались последние 16 слоёв, в специализированной — последние 8 слоёв.

Функция потерь объединяет pairwise loss с весами, учитывающими изменение NDCG@10, и listwise loss в пропорции 0.7 и 0.3 соответственно.

Для специализированной модели дополнительно использовались сложные отрицательные примеры, отобранные на основе оценок предобученной модели и лексического сходства.

## Промежуточные эксперименты

### V10

На данном этапе исследовалось ранжирование полного списка документов с учётом информации о статье и последующим объединением оценок.

Полученные результаты стали основой для перехода к двухэтапному ранжированию. Сопоставимое значение метрики V10 в сохранённых результатах отсутствует.

### V11

Добавлена специализированная модель для повторного ранжирования короткого списка документов.

Также проверялось влияние порядка документов на предсказания модели. Для уменьшения этого эффекта использовался инференс в прямом и обратном порядке.

Рассматривались различные варианты объединения предсказаний двух моделей.

### V12

Дополнительно были протестированы Answer Evidence Reader и cross-encoder.

Подключение дополнительных моделей не позволило улучшить результат V11. Поэтому в следующей версии было принято решение сохранить архитектуру из двух моделей Jina.

### V13

В финальной версии были увеличены вычислительный бюджет и полнота повторного инференса.

Добавлены:

- дополнительный проход для сложных запросов;
- увеличение контекста до 5120 токенов;
- адаптивное объединение предсказаний;
- остаточная калибровка итоговых оценок.

## Итоговое решение

В качестве итогового метода используется Residual Calibrated.

На первом этапе основная модель ранжирует полный список документов. Затем формируется короткий список из 6 или 8 документов, для которого выполняется дополнительное ранжирование.

Для уменьшения зависимости результата от порядка документов используются предсказания, полученные при различных последовательностях входных данных.

Итоговые оценки корректируются с помощью остаточного калибратора, который учитывает:

- различия между предсказаниями двух моделей;
- позиции документов в ранжировании;
- согласованность результатов нескольких проходов;
- результаты дополнительного инференса;
- лексическое сходство запроса с текстом и заголовком документа.

Калибратор обучается с использованием регуляризованной попарной логистической функции потерь.

Документы за пределами короткого списка сохраняют порядок, определённый основной моделью.

## Воспроизведение результата

Для установки необходимых библиотек:

```bash
pip install -r requirements.txt
```

Для запуска необходимо:

1. Подключить исходные обучающие и тестовые данные соревнования.
2. Включить GPU T4 x2 и доступ к Интернету.
3. При необходимости указать пути к исходным данным.
4. Выполнить все ячейки solution.ipynb последовательно.

Предварительно обученные адаптеры и файлы предыдущих экспериментов не требуются.

В ноутбуке предусмотрено ограничение вычислительного времени в 290 минут. При использовании другого оборудования объём дополнительных вычислений и итоговый результат могут отличаться.

Полный повторный прогон с requirements.txt в отдельном окружении не проверялся.
